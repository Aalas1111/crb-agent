# 项目规范：判断归 LLM，程序不越界

> 这份文件只讲这一条纪律，以及它在这个项目里**具体落在哪一行代码上**。
> 完整来历（含被否决的反例与那次事故）见上游
> [`yuque-agent/docs/principles.md`](https://github.com/Aalas1111/nju-yuque-agent/blob/main/docs/principles.md)，
> 这里不复制，只写本项目怎么用。

## 1. 一句话

**程序只做「可测量的事实」；语义判断全归 LLM。禁止在程序层对 LLM 的输出做语义审查。**

## 2. 在这个项目里，这条纪律落在三处

| 层 | 它是什么 | 允许的力度 |
|---|---|---|
| **工具注册表**（`tools.py`） | 「agent 能做哪些事」——粗粒度、可测：有 / 没有这个工具 | 这是本项目安全性的落点 |
| **提示词**（`prompts/system.md`） | 规矩 + 为什么 + 正反例：默认只存草稿、`duplicate` 不是错误、不编事实 | 文案类规矩**只**写在这里 |
| **守卫测试**（`tests/test_prompt_guard.py`） | 盯「契约与提示词漂没漂」 | **不动运行时行为** |

## 3. 明确禁止

* ❌ 在工具层 / 事件层对 LLM 说的话做字符串或正则过滤（比如「出现『已办结』就拒收」）。
* ❌ 用代码判断「这条申请该不该去重」。程序能说的是**事实**：
  「这两条活动的日期与节次完全重叠」；该不该合并成一条，是**判断**。
* ❌ 把结构化校验写成语义拦截。校验**结构**（必填字段、枚举、JSON 合法性）是对的；
  判断**内容对不对**不行。

## 4. 这条线在代码里的样子（正反对照）

**对**——`crb plan` 发现两条活动同时段时，程序只加一句事实到 `note`：

```
note = "与同一批次里的「先来」时间重叠"
status = "ok"        # 照样排教室：同一次活动开两间教室是合理的
```

**错**——程序自作主张把它们合并成一条，或者因为「像是重复」而拒收。

**对**——模型给出坏 JSON 参数时，工具回一句「参数不是合法 JSON」让它自己改
（`llm.ToolCall.arguments()` → `tools.Toolbox.execute`）。

**错**——在程序里猜它的意图、替它补全参数。

## 5. 改代码前的自问

1. 这件事是**测量 / 算术 / 查表 / 留痕**，还是**语义判断**？后者不该写成 Python。
2. 我要加的约束，是「这个工具不存在」（粗粒度、可测），还是「我不喜欢它这么输出」（语义）？
3. 这个规矩能不能只写在提示词里 + 用守卫测试盯着？**能就别写进程序。**
4. 动了提示词里的规矩：**正例、反例、规矩块必须一起改**，并跑 `tests/test_prompt_guard.py`。
